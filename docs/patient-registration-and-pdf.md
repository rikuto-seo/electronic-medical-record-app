# 患者登録とPDF出力

## 登録・編集

- 新規患者登録を基本情報、連絡先、診療に必要な情報に整理。患者番号、フリガナ、職業、担当、紹介元、既往歴、アレルギー、服薬、家族歴、保険情報、申し送りを追加。
- 氏名・性別・生年月日・初診日が必須。空白だけの氏名、不正な日付、未来の生年月日、生年月日より前の初診日を拒否。
- 患者番号は任意。取得済みの患者一覧にある同番号を検出する。複数スタッフの同時登録を保証するデータベース側の一意制約は未導入。
- 保存中は入力・連打を抑止。エラー時も内容とドキュメントIDを保持するため、再送で別の患者を作らない。
- 保存完了後、患者詳細へ移動。Firestoreへの不要なポーリングを廃止。
- 患者詳細の「患者情報を保存」で同じ項目を編集可能。患者情報更新ではカルテ配列を書き戻さない。
- 患者データの再取得時も、編集中の患者情報と入力中のカルテを消さない。
- Firestoreに保存できないundefinedと画面用のmediaFiles/hasReservationを除外。
- 登録時の年齢は互換性のため保存するが、一覧と患者情報PDFは生年月日から日本時間の当日年齢を再計算。
- 空欄は未記載。「なし」や「異常なし」を自動生成しない。

## 患者一覧からの出力

- 「患者情報PDF」: A4縦・1ページの患者情報シートを直接ダウンロード。
- 「患者情報の確認」: 同じ情報の確認画面からダウンロード。
- 「カルテPDF」: 診療記録を選び、患者情報シートを先頭に付けるか指定してダウンロード。
- 患者詳細では、各カルテ単独またはチェックした複数記録を出力可能。
- 旧URL `/print/:patientId/:recordIds` のパラメーターを正しく読み取る。存在しないIDを含む選択はエラーにし、全件出力へ戻さない。
- 出力中の連打を防止。失敗理由は画面に表示し、再出力可能。

## PDFの仕様

- jsPDFとローカルのNoto Sans JPを使ったテキストPDF。日本語を検索・コピー可能。外部PDF変換サービスは利用しない。
- 患者シートには住所、電話、メール、緊急連絡先、注意事項、服薬、既往歴、保険、申し送りをまとめる。既存の構造化保険情報、生活習慣、身体計測も存在すれば出力。
- 患者シートは10ptから8ptの範囲で自動調整。収まらない場合は切り落とさず要約を依頼するエラーを表示。カルテ本文は表紙なしでも出力可能。
- 表紙に収めるための自動要約・診療情報の省略は行わない。
- カルテは記録ごとに改ページ。非常に長い項目は続きページへ分割し、見出しとページ番号を付ける。
- 疼痛0、鍼0本、バイタル、施術担当、経過、有害反応などを出力。記録はすべて「診療記録」と表示する。
- 添付ファイルは件数を表示し、画像・動画・ファイル本体はPDFへ埋め込まない。
- フォント未対応の文字は黙って消さず、出力エラーで知らせる。
- ファイル名は患者番号（あれば）、氏名、出力日、帳票種類。禁止文字を置換。
- ブラウザー上の「出力内容」画面とPDFは同じデータを使用するが、改ページ・用紙レイアウトはPDF生成時に計算する。

## 検証

```powershell
npm.cmd run typecheck
npm.cmd test -- --watchAll=false --runInBand
npm.cmd run build
node scripts/verify-patient-pdfs.cjs
python scripts/inspect-patient-pdfs.py
```

最後の2つは架空データから実際の生成処理でPDFを作り、日本語・全長文・用紙サイズ・余白・ページ数を検証してPNGへ描画する。生成物はgit対象外の `tmp/pdfs/`。Pythonの検証にはPyMuPDFが必要。

実患者の登録、実環境のFirestore書き込み権限、ブラウザーのダウンロード操作は、認証済み環境で確認する必要がある。
