# 院内予約管理

`/reservations` に日・週表示の予約表をまとめています。旧 `/calendar` は週表示へ移動します。

## 最初の設定

「院内設定」で担当スタッフ、ベッド・施術室、施術メニューと所要時間を登録します。
初診60分、再診30分、鍼灸45分は編集可能な初期値です。院の運用に合わせて変更してください。
使用停止にした担当者・メニューも、過去の予約では表示されます。

## 受付の操作

- 患者の氏名・ふりがな・患者番号・電話番号から検索し、日時・担当者・ベッドを指定します。
- 来院、施術中、終了は予約行のボタンから進められます。
- 変更・キャンセル・無断キャンセルは「編集」から行います。キャンセル理由も記録できます。
- 「次回予約」は患者・メニュー・所要時間・使用中の担当者・ベッド・時刻を引き継ぎ、1週間後を初期値にします。日時は保存前に変更できます。
- 「カルテ」から既存の患者詳細へ移動できます。

日時は日本時間で統一しています。検索・担当者・状態の絞り込みは予約表の表示に作用し、上部の件数は表示期間全体の集計です。

## 互換性と保存

既存の `reservations` コレクションを使用し、新しい項目は追加のみです。
`checkedIn` しかない旧予約は予約または来院として読み込みます。新しい状態を保存する際も旧項目を同期します。
キャンセルは削除せず状態を変更し、履歴を残します。

新たに次のFirestoreドキュメントを使用します。

- `clinicSettings/reservations`：院内の共通設定
- `clinicSettings/reservationRevision`：複数端末の予約更新の競合確認

既存のスタッフ認証・権限に合わせて、上記ドキュメントの読み書きを許可する必要があります。
`firestore.rules` に、指定された院内スタッフUIDで患者・予約・上記設定ドキュメントを読み取り・作成・更新できるルールを用意しています。詳細は `docs/firestore-access.md` を確認してください。Firebase側への公開はまだ行っていません。
権限が足りない場合は画面にエラーを表示し、保存は成功扱いにしません。

同じ患者・担当者・ベッドで時間が重複する予約を拒否します。未指定の担当者・ベッドはその資源の重複確認対象外です。
終了時刻と次の開始時刻が同じ場合は予約できます。キャンセル・無断キャンセルは枠を占有しません。
重複判定は画面だけでなく保存時にも行い、サーバーの予約一覧取得後に別端末が更新した場合は再取得・再判定します。
予約と共通revisionを同一トランザクションで保存するため、ネット接続が必要です。
この競合確認は新しい保存処理を使用する端末間で有効です。旧バージョンからの書き込みと併用しないでください。
予約・院内設定の古い編集画面からの上書きも拒否します。

## 確認方法

```powershell
npm.cmd run typecheck
npm.cmd test -- --watchAll=false --runInBand
npm.cmd run build
npm.cmd start
```

テストは重複・境界時刻・日付跨ぎ・旧データ・競合保存と受付画面の操作を確認します。
Firestoreはテストで置き換え、実患者データへの書き込みは行いません。
ログイン後の実環境での権限確認・複数端末での保存は別途確認が必要です。
