# 3D解剖表示の現状と改善案

この文書は改修前の調査。実装した変更と現在の操作は [anatomy-improvements.md](anatomy-improvements.md)、元データの修正履歴は `anatomy-data-corrections.json` を参照。

確認日：2026年10月10日。対象は `AnatomyViewer.tsx`、`Model.tsx`、13個の部位JSON、`public/models/bp3d/glb`。
コードと全モデルファイルを静的に確認した。接続できるブラウザーがないため、実画面の形状、解剖学的な位置関係、実測の表示速度・GPUメモリは未確認。
現在の数値は `anatomy-audit.json`、改修前に存在した58件の不整合な部位情報は `anatomy-data-corrections.json` に記録している。再確認は `node scripts/audit-anatomy.cjs`。

## できていること

系統・領域ごとの部位選択、部位名の検索、個別・系統の色変更、回転・移動・ズーム、部位をクリックして名称と分類を表示できる実装がある。
選択した部位だけのGLBを読み込む。最初の選択は空なので、起動直後に全モデルを読み込む実装ではない。
GLBは3,210ファイルあり、ヘッダー・JSONチャンクを検査した範囲で異常は0件。形状の臨床的な正しさを確認した結果ではない。

## まず直す問題

1. **存在しないモデルを選択できる。** 部位情報3,268件に対してGLBが58件不足している。大胸筋の一部や動脈に欠損がある。選択時にURLを直接組み立てるため、不足ファイルをそのまま取得する。部位ごとのエラー境界がなく、ひとつの失敗が3D全体に波及する可能性がある。まずモデル台帳を用意して欠損を表示し、他の部位は表示を続ける。
2. **骨盤部が一覧に出ない。** 固定の領域リストに「骨盤部」がなく、右内腸骨静脈の2件が子一覧から漏れる。親分類の一括選択には含まれるため、一覧と実表示が食い違う。データから領域を生成し、表示順だけを別設定にする。
3. **カメラが全体の大きさに合わせていない。** 初期位置は `[5,5,5]`。読み込まれた最初の部位に一度だけ回転中心を合わせ、バウンディングボックスの大きさを使って距離を調整していない。追加した部位にも追従しない。全体に合わせる／選択部位に寄る、正面・背面・左右、視点リセットを最優先で用意する。
4. **初期画面が空で、始め方が分かりにくい。** 最初から全身を読み込む必要はないが、骨格または対象領域のプリセットと、選択・解除・視点の簡単な案内が必要。

## 臨床で使うために足したい操作

- 肩、頚部、腰、股関節、膝などの領域プリセット。左右を選び、関連する骨・筋・神経・血管をまとめて表示する。
- 選択部位だけ表示、周囲の構造を半透明にする、皮膚・骨・筋を段階的に隠す。現状は表示／非表示と色変更だけで、深部構造の確認が難しい。
- 部位の選択とカメラの回転を区別する。現在は `onPointerDown` で選択するため、回転を始めるときにも部位を選んでしまう。
- 検索結果を専用の一覧に出し、該当分類を開いて対象に寄れるようにする。現在は閉じた分類の中を絞り込み、系統の親チェックは検索結果以外もまとめて選択する。
- 部位名のラベル、左右・方向表示、現在の表示部位数、読込進捗と失敗した部位の再読込。
- 表示設定とプリセットの保存。院内スタッフがいつも同じ準備操作を繰り返さずに済むようにする。

## 情報の不足と整理

全部位の説明文・画像・参考リンクは0件。現状の詳細パネルは名称・FMA ID・分類・親構造が中心で、臨床説明の内容は未登録。
起始・停止・作用・支配神経、隣接関係、関連する観察・評価などは、対象領域から段階的に追加する。内容は臨床経験と出典に基づいて確認してから登録する。
動脈と静脈は同じ「循環器系」にまとめられ、同じ初期色になっている。両者を分けて表示・色を選べるようにする。
`middleCategory` や `order` がデータにあるが、UIの領域分類は主に `region` を使っている。分類、表示順、親子関係の用途を明確にし、名称・左右・識別子の整合性を検査する。
元データの版、変換手順、出典とライセンスを記録する。今回、モデル配下にREADMEやLICENSEは見つからなかった。これだけで権利状態を判断することはできない。

## 表示性能と保守

全GLBの合計は192,236,556 bytes（約183.3 MiB）。三角形定義は合計約865万で、同時表示・通信量の実測ではない。
最も大きい単体は皮膚の約4.7 MiB・203,382三角形。一括選択すると多数の部位を同時に読み込むので、対象領域を絞るプリセットと段階的な読込が効果的。
現在は色変更のたびに全メッシュへ新しいマテリアルを割り当て、古いマテリアルを解放していない。`dispose={null}` とGLTFキャッシュも使っているため、材質を一度作って色を更新し、所有する材質だけを適切に解放する形に直す。
`onLoaded` の関数が描画ごとに変わり、モデルの境界計算が再実行される。イベント処理と材質・カメラを分け、安定したコールバックにする。
常時描画・影付き描画を使っている。操作していない間の描画停止、影の品質設定、圧縮・簡略モデルは、実機の速度と形状を比べてから選ぶ。
データ台帳、選択状態、カメラ、読込、情報パネルを分け、欠損ファイル、分類、プリセット、選択と回転、再読込を検証できる構成にする。
